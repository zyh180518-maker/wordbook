2026-10-22 · 22:06起点：一个 docx 里的 1300 个单词

第一条需求原话：

这是我平时在手机上记录的英语单词（个人记录.docx）。我希望你做一个类似软件的东西，功能就是我把英语和翻译写进去，然后它给我记着，然后我会想让他随机给一个我收录的英语，然后我翻译或者反过来（不清楚工作量有多大，做这个软件你得做到某一个阶段就保存一下，防止模型出现中断）。如果单词和翻译同时弄的话软件会很麻烦的话，你就退而求其次……

当晚 22:11 第一版就落在 wordbook/index.html。同一句话里定下的两条规矩，后来贯穿全程：

  • 阶段性保存，防止中断丢进度 → 演变成「每版先备份、绝不覆盖、.bak-before-* 命名」
  • 先给大纲问可行性再动手 → 演变成「方案先报、方向不对就停下来对齐」

第一版形态：单文件 HTML + localStorage，零依赖，双击即用。功能已经齐了：内嵌种子词（源自那份 docx，清洗后 1292 个）、加权随机抽词、√/× 作答、艾宾浩斯复习间隔、统计与连续打卡、搜索 / 收录 / 批量导入、JSON 导入导出备份、答错强制补译文、深色主题。

手机怎么用是当晚第一个真问题。解法是 启动-手机用.bat：起一个 8765 端口的局域网服务，手机连同一 Wi-Fi 打开地址；或者在微信里直接打开 HTML（这条路径后来解释了为什么要做「从微信浏览器导出备份」的迁移流程）。

10-22 夜 ~ 10-23 下午01 · 纯网页阶段

改了两轮：先加应用图标（15:41，改前存 .bak-before-icon），再给「清空重来」加可选默认词库 / 归零（17:40，存 .bak-before-reset-choice）。

另一条线在并行：另一个对话整理了一份移动端优化建议清单（优化建议.md），把「手机上一天用几十次」的痛点排了优先级。落地了三项：底部固定答题栏（拇指友好）、主动回忆模式（先自测 → 看答案 → 再判 √/×）、手滑 5 秒内可撤回（配 Z / Ctrl+Z 快照恢复）。

也在这时清理了种子词库里的脏数据：拼错的（civillisation、obaolete）、缩写残词（can't、i'll）、碎片（ial、hydr、againsta）。这是第一次「数据比代码更麻烦」的提醒，10 天后它会变成整场的主要工作量。

遗留问题记在当时：答错强制填译文 × 5 秒撤回存在交互竞态（输入框被重建，译文可能写到别的词上），给了 A/B/C 三种修法，最终选了「填译文时先移除撤回钮」。

10-23 · 16:42 ~ 20:1002 · 变成真 App，和一场签名事故

动机很直接：手机浏览器用着费劲。于是 16:42 建仓库 wordbook-github，Capacitor 6 + GitHub Actions 自动打包 APK，第一个版本 v1.0.0。

签名事故是这一阶段最重要的收获：v1.0.0 / v1.1.0 / v1.2.0 每次 CI 构建都用随机 debug 签名，手机上装过旧版后新版根本覆盖不上，只能卸载重来（数据全丢）。修了两轮：

  • 第一轮只把 keystore 复制进工程，没改 Gradle 的 signingConfigs → 不生效
  • 第二轮 scripts/patch-signing.py 显式注入 PKCS12 → 生效

v1.3.0 是分水岭：指纹 O=Wordbook、SHA256 44:78:05:F0:…:E4:06，从此新版可以覆盖安装、数据保住。当时写下三条硬约束，一直延续到最后：keystore 丢了就永远无法平滑升级（唯一单点风险）；每版必归档到 backup/apk/ 且永不覆盖；回档路径始终可走。

顺带记录了第一次网络坑：git 没继承系统代理，push 一直超时；后来所有 GitHub 操作都显式走代理或直连。

10-23 夜 ~ 10-2503 · 自动更新链

这一阶段的目标是「以后改界面不用重装 App」。v1.4.0 一次上了三件套：前端热更 + APK 全量自更新 + CI 发布链。

热更的做法：head 里一段启动器，启动时拉 latest.json，比对版本、下载新 HTML、用 MD5 校验原始字节，再 location.replace(Blob URL) 整页替换。校验不过就删缓存回滚，成为「自愈」。

几个坑全在实测里撞出来，后来都写进了硬规矩：

  • 不能用 document.write 换页——同 window 下 const 重复声明直接 SyntaxError，只能走 Blob URL
  • MD5 必须对原始字节算（arrayBuffer），不能 text() 后再编码
  • Python 生成 MD5 必须二进制模式，文本模式把 \n 变成 \r\n，永远对不上
  • UPDATE_URLS 大小写不一致（定义 var 大写、调用小写）导致按钮卡死
  • 备份源一开始指向 main/www，而 CI 只推 gh-pages → 未来必然 404

CI 侧三次构建失败也全是真问题：Capacitor 6.2+ 的 MainActivity 变成空类（脚本找不到 anchor）、TtsBridge 的 final 字段在 lambda 里被判「可能未初始化」两次。最终把语言/语速配置延迟到首次 speak() 执行才绕过去。为了让失败可诊断，workflow 里加了「把 gradle 报错写成 annotation」，匿名就能在 run 页面看到错误。

10-24 三个小版本接着修：v1.4.1 治「点发声没声音」（4 个根因：无兜底、引擎未就绪不回读、二次点击覆盖文本、语言 fallback 不看返回值）；v1.4.2 加「今日已学 / 学习记录」；v1.5.0 一次做七件事（使用说明重写、朗读模式手动/自动、更新入口独立、音色优化、记录整行可点 + 删除防误触…）。

10-25 是「国内能不能用」的一天。Gitee 做了镜像源（v1.5.1），结果发现 Gitee raw 没有 CORS 头：curl 能下、App 不能下。解法是启用 CapacitorHttp（App 内 fetch 走原生、绕开 CORS）并把备份源做成逐级兜底。另一个细节：Gitee API 覆盖已有文件必须用 PUT，且 sha 要传完整 40 位，截断就静默失败。

同一天还做了一次「降级升级链」回归：关掉代理模拟国内环境，用 v1.4.0 / v1.4.2 / v1.5.0 / v1.5.1 四个旧版本逐个往新版升——全失败。根因是这四个老版本的启动器没有兜底链，而主源当时指向 Gitee。修法是把 htmlUrl 主源改回 GitHub Pages（国内可达 + CORS *），Gitee 降为备份。改完 9 个版本逐个升级，全通。

这一串 7 连发之后：导出备份改成「真文件 + 系统分享」（@capacitor/filesystem + @capacitor/share），兜底还加了 gzip + base64 压缩；每日单词数可自定义（1–999）。

10-25 ~ 10-2804 · 从背单词到备考

v1.5.7 把学习逻辑做厚：遗忘曲线 / 完全随机两种抽词模式、✓× 可自由改判（但必须写意思）、记录可改掌握状态并筛选、多次未掌握（≥2 次）单独成表。

v1.6.0 加了「记忆方式」：系统直接给释义，判完自动显示，不用手写；同时内嵌 3 万词词典（dict.json，最终 31290 条），收录新词自动匹配释义，个人手写释义不被覆盖。

10-29 先补工具链：JDK17 + Android SDK + adb 装到本机（不再干等 CI），加 qwen2.5-coder:7b 当第二双眼睛复核代码，写了个 10 项自检脚本。这套后来所有版本都在用。

内容是这一天的主角：四六级初始词库（四级 4544 / 六级 6662 词）、六级真题模块（第一版 35 套 1228 题）、听力原文阅读（四级 29 套 / 六级 28 套）、备考专区 + 试卷式整卷展示。

09 · 踩过的坑

签名与安装

  • 随机 debug 签名 → 覆盖安装失败；修法必须是显式 signingConfigs（PKCS12）
  • 本地测试包必须按 CI 规则打 versionCode（主*10000+次*100+补丁），否则低于已装版本装不上
  • 本地测试包必须用仓库那把 keystore，否则报签名不一致

热更新

  • document.write 会撞 const 重复声明 → 只能 Blob URL + location.replace
  • MD5 对原始字节；Python 必须二进制模式
  • 主源不能放 Gitee raw（无 CORS）；Gitee 覆盖文件用 PUT + 完整 40 位 sha
  • 老版本启动器没有兜底链 → 主源一变全挂；于是主源固定在 Pages、Gitee 降备份
  • blob: 页面里相对路径全部失效

WebView / 原生

  • HE-AACv2 不支持（MediaError 4）→ 只能用 AAC-LC
  • TTS 引擎 0.5–3 秒才就绪，必须「就绪后回读 pending」+ 前端 isReady() 兜底
  • Capacitor 6.2+ 空类 MainActivity 让注入脚本失效

数据

  • 想当然的完整性：三选项题、空题干、空号——最后都改成「缺就明示」，宁缺勿假
  • 标准答案泄露、选项掉出题块、词表被压成 A）、整段正文丢失
  • PDF 抽行粘连 1000+ 处；OCR 折行把选项甩出题块

工程

  • CRLF 让四份副本 md5 不一致（core.autocrlf=true 改写了 www/index.html）
  • 四副本必须逐一核对 md5
  • 批量脚本中断会留半成品，重跑前先校验产物，别让「已存在即跳过」固化空文件

10 · 留下的硬约束

  • 每版先备份、永不覆盖（.bak-before-* + backup/apk/ 归档）
  • 改完必自检：语法、幂等重跑、四副本 md5、真机实测、线上产物核对
  • 数据变少一律当退化，说清「减了什么、为什么」
  • 宁缺勿假：没录到的题就标缺，不编内容
  • 数据或音频改动 → 只能整包重装；纯 HTML 改动 → 应用内热更
  • keystore 不能丢（唯一单点风险）

11 · 结语

12 天，从一个 docx 里 1300 个单词，到 32 套真题、1035 道题、53 段音频、325 MB 的离线 App。中间大部分时间其实不在写功能，而在把不完整的数据补完整、把假象去掉、把每处改动验证到底。
